## Deck Integration

[The PowerPoint generator](../build_deck.js) requires the two final-recording assets. Slide 2 of
[the browser companion](../mosaic-challenge-deck.html) displays both authentic frames and states
their limits. The three-slide PowerPoint is checked for text bounds and text overlapping images,
inspected at 1280 by 720, exported at 3840 by 2160 and exported to
[the PDF deck](../mosaic-challenge-deck.pdf) with desktop PowerPoint. File-format names are
explained in the [glossary](../README.md#plain-language-glossary).

The media package uses [mosaic-output.png](../mosaic-output.png), a screenshot of the real generated report's unanswered-question section. It is generated by [the browser capture script](../../scripts/validate_presentation.js) at a verified page width of 1440 pixels and two image pixels per page pixel. The script checks the current separate report pages for three options, four unanswered questions and an awaiting-human-review state before capturing the question section. UNK in the image means unknown: an unanswered question. This screenshot is generated example output, not application footage or evidence of real customer use.

This capture does not show an online request, a complete planning session, proposed code changes, automated build checks, or reviewer corrections. Those scenes and the application version record remain separate scoring opportunities. Passing media checks do not authorize customer release or contest submission.

For future full-screen video and capture, target 1920 by 1080 or higher at native resolution. Do not include notifications, account details, customer information, tokens, local usernames, unrelated repositories, tenant details, or a mock interface.
